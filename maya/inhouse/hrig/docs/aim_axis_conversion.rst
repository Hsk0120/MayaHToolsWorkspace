Aimの1〜2軸変換
=================

``HTools > rigging > convertAimAxes`` で、選択した既存のaimConstraintの
回転出力を1軸または2軸へ変換します。既存Aimを計算元として残し、その後ろへ
標準DGノードを挿入する構成です。hlibのNode・Plug・Container・ScalarGraphを使います。

操作
----

1. ジョイントではなく **aimConstraintノードを1つ選択** します。
2. ツールを起動し、必要なら「選択したaimConstraintを読み込む」を押します。
3. 方式1/2/3と出力軸（X・Y・Z・XY・XZ・YZ）を選びます。
4. 「変換／方式を切替」を押します。対象が動くので、ターゲットを動かして比較します。
5. 別方式を選んで同じボタンを押すと、元の接続へ戻してから新しい方式を構築します。
6. 「元のAim構造・設定へ戻す」で、変換と補正の所有ノードを全て削除し、
   元のaimConstraintからの直接接続と設定値を復元します。

変換・切替・復元はそれぞれ1回のUndo/Redoに対応します。
画面は自動更新しません。「結果を再確認」で現在フレームの値と診断を表示します。
メニューに未反映のセッションでは、Pythonで開けます。

.. code-block:: python

   from HTools.rigging import convertAimAxes
   convertAimAxes.run()

方式の違い
----------

.. list-table::
   :header-rows: 1
   :widths: 22 45 33

   * - 方式
     - 計算
     - 設定と注意
   * - 1: Eulerの等価解
     - 元の全回転と等価なXYZ一組を2候補作り、指定軸の範囲に合う組を選ぶ。
     - 基準XYZと許容半幅は度。既定0度・±85度。
   * - 2: ヒンジ／2軸方向
     - 元の全回転で指定した方向を変換し、1軸なら平面投影角、2軸なら順序付きの角を求める。
     - 回転Xなら狙う軸Y/Z。回転XYなら狙う軸Z。符号も指定可能。
   * - 3: 軸別Twist
     - 元のQuaternionを各選択軸へ独立に射影してねじり角を得る。
     - 2軸は独立したTwist角。Swingの2成分でも元Eulerの2成分でもない。

方式1は各軸を独立に180度補正せず、XYZ一組の等価解を選んでから必要軸を使います。
範囲内の候補が1つならそれを採用し、0個または2個なら基準への二乗距離が小さい組を採用しつつ
``valid=0`` を返します。これらの場合は正しい枝を一意に決められていません。
境界をまたぐ範囲・ジンバル特異点・本当に必要な大きい回転を自動で連続化する機能ではありません。

方式2の基準は、選択軸以外を0とした回転です。未選択軸へ残した固定回転や
「変換時の角度を維持」の加算がある場合、最終姿勢の方向と元Aimの方向の完全一致は保証しません。
2軸の適用順は対象のRotate Orderから未選択軸を除いた順です。
先に適用する角を±90度に収め、後の角を±180度で求めます。極では後の角が不定になります。
元AimのjointOrient・Offset等を補正した ``constraintRotate`` を入力にしており、
生のターゲット位置から新しいaimConstraintを作り直す機能ではありません。

方式2・3の「変換時の角度を維持」は、計算角へ一定の角度を加える機能です。
MayaのMaintain Offsetと同じ行列計算ではありません。チェックを外すと各方式の生の値を比較できます。
方式1ではこのチェックを使用しません。

接続と復元
----------

復元時は元Aimが駆動していた軸へ直接再接続し、元々未接続だった軸は保存値へ戻します。
変換ノード・補正ノード・所有containerは全て削除します。
元Aimの未接続設定（Rest Rotate、Offset、Aim/Up Vector、World Up、ターゲットウェイト等）を
変換時に記録し、設定値も復元します。入力接続で駆動される設定はその入力を維持します。
保存した値を戻す際に新しい入力やロックがある場合は、変更を壊さないよう復元を拒否します。
旧版の補正付き復元からも、同じボタンで元Aimだけの構造へ戻せます。
旧形式で未記録だった設定は推測して変更せず、元Aimに残っている値を使用します。
復元後の接続された回転は元Aimが現在のターゲットから計算します。追加のEuler補正は行いません。

選択軸には変換出力を接続します。未選択軸の元Aim接続は外し、変換時の値に固定します。
未選択軸にある他の入力は維持します。選択軸に別の入力がある場合は変換を拒否します。
ロック・参照ノード、複数の直接出力対象、pairBlendやunitConversionを介する間接接続は未対応です。

生成物は専用containerが所有し、元Aimと対象は所有下へ入れません。
message接続で参照するため改名・シーン保存読込後も復元できます。
変換後に対象への入力接続を手編集した場合、別の接続を壊さないよう復元を拒否します。
container内のノード・設定は手編集せず、画面から方式を切り替えてください。

元の循環接続やWorld Upの特異点は解消しません。前フレームの記憶・多回転の蓄積・
±180度をまたぐアンラップも行いません。方式2・3の特異点では計算角を0にして
``valid=0`` とします。姿勢維持を指定した場合はその固定加算値が残ります。
Rotate Order変更時も ``valid=0`` になるため、再変換してください。

Python API
----------

.. code-block:: python

   import math
   from hrig.setups import AimAxisConversion

   graph = AimAxisConversion.create(
       "neck_IK_jnt_aimConstraint1",
       axes="xy", mode="euler",
       reference=(0, 0, 0), half_range=math.radians(85))
   # sourceは元のaimConstraint。既存変換があれば安全に復元して切り替える。
   graph = AimAxisConversion.create(
       "neck_IK_jnt_aimConstraint1",
       axes="xy", mode="direction", direction="z", preserve_pose=False)
   graph.restore()

``restore()`` は元の設定値と直接接続を復元し、生成物を削除します。戻り値はありません。

APIの角度引数と ``outputX/Y/Z.get()`` はラジアンです。
``valid`` は現在フレームの範囲・特異点・回転順序の診断で、リグ全体の正しさや
サイクルの有無を保証するフラグではありません。

テストごとにシーンを新規作成します。GUI内の既存シーンへ送信してはいけません。

6回転順の数値・3方式・Undo/Redo・復元・単位・保存読込・GUI操作を検証します。
