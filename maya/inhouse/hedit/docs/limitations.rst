現在の制限
==========

機能
----

* Python と MEL の実行に対応しています。 **MEL の補完・MEL の静的解析、デバッガー、LSP、VS Code 拡張機能は未対応** です。
* 型の推論は、クラスの呼出しの代入(``x = pkg.Class(...)``)と型ヒント(変数・引数)だけです。関数の戻り値(``hlib.ls()`` など)・添え字・条件で変わる変数は推論しません。
* zip 内のソース、まだ読み込んでいないバイナリ拡張、\ ``__getattr__`` で生成される未知の属性は、完全には補完できません。
* 補完は静的な名前の候補です。型や構文が正しいことを保証しません。
* インデント幅は 4 空白で固定です(変更できません)。
* マルチカーソル(Ctrl+D など)、コード整形、画面の分割、コマンドパレット、参照の一覧、名前の一括変更は未対応です。
* 定義へ移動は、編集中の本文と、ソース(``.py``)のあるモジュールが対象です。\ ``maya.cmds`` のようにソースの無い名前、
  関数の戻り値の型を経由した名前には移動できません。関数の中の変数は、カーソルより前の代入・引数・for などを探します。
* 未定義の名前の検出は、モジュール全体で定義の無い名前だけです(定義より前に使っている・条件によって定義されないなどは
  検出しません)。Maya の ``__main__`` にある名前は定義済みとして扱います。
* 折りたたみはインデントで決めます(VS Code の既定と同じ)。畳んだ状態は保存しません。行の移動・削除などの行の操作をすると開きます。
* 見出しの固定表示に出すのは、クラス・関数(MEL は proc)の見出しだけです(最大 5 行)。
* 保存前との差分は、開いた・保存した時点のファイルの内容と比べます。ほかのアプリでファイルを変えても、印は更新しません。
* 色分けは Python / MEL の字句解析による強調です。Pygments や VS Code の意味解析と完全に同じ色分けにはなりません。
* 検索・置換は現在のタブの中だけが対象です(複数ファイルの検索、検索語の履歴はありません)。

動作
----

* スクリプトの実行は Maya のメインスレッドで行うため、長い処理の間は Maya が待機します。
* 補完・静的解析も Maya と同じプロセスのメインスレッドで行います。補完は C++ で行うため大きなファイルでも数ミリ秒ですが、
  遅いネットワークパス上の未読込のモジュールを初めて読むときや、静的解析(Python の ``compile()``)の間は、
  Maya の操作も待機します。重いと感じたら、該当する設定をオフにしてください(:doc:`preferences`)。
* 宣言の読み取りは C++ の簡易な字句解析です。Python 3.12 の f-string の中で同じ引用符を入れ子にした書き方などは、
  正しく読めない場合があります(色分けと補完候補だけに影響し、実行には影響しません)。
* C++ プラグインは Python の ``reload()`` では更新されません。hedit の Python 部分もプラグインに同梱しているため同様で、
  更新には Maya の再起動が必要です。
* ``import hedit`` は、\ ``hedit`` プラグインをロードした後でないと使えません(:doc:`install`)。

環境
----

* Windows の Maya 2022(Python 3)/ 2023 / 2024 / 2025 / 2026 / 2027 で確認済みです。
* スペルチェックは Windows 標準の英語辞書を使います(macOS / Linux では使えません)。
* Mac・Linux 用のプラグインはビルドしていません。
* Maya 標準のスクリプトエディターの全機能を再現するものではありません。
