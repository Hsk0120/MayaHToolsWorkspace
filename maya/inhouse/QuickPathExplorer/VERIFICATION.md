# C++版の検証

検証結果はQtプログラム操作、Maya API操作、WindowsのOS入力、実プロセス再起動を分けて記録します。未実施の条件を合格に含めません。旧Python版のテスト結果をC++版へ転用しません。

## Windows／Qtの自動回帰

QuickPathExplorer直下で次を実行します。Qtとメディアの初回ビルドは[BUILDING.md](BUILDING.md)を参照してください。

```powershell
py -3.12 tools/build_cpp_windows.py --product --test
```

`tests/cpp_migration_test.cpp`を静的Qtで構築し、CTestで実行します。各ケースはビルドフォルダー内の専用一時領域を使い、ユーザー設定と実データを使用しません。結果は`.maya-output/cpp-windows/test-results.txt`です。旧テストの`tools/qpe_ui_*.py`を製品の検証入口には使用しません。

| 分類 | 回帰で確認する内容 |
|---|---|
| 列挙・表示 | 100件からの段階表示、A→B→A、世代と完了順序、空／日本語／多数項目、エラー、別タブ、破棄 |
| 操作・配置 | 戻る／進む、タブ独立状態と詳細の同期、初回の祖先選択可視化、手動スクロールと履歴位置の保持、場所ロック、列幅、グループ、検索条件、表示密度、狭幅の詳細全幅表示 |
| 入力 | 編集欄と外部Qtへのキー非干渉、一覧内改名、Enter／Escape、模擬IME変換、全選択解除後を含む操作対象、クリップボード占有中の再試行と世代 |
| ファイル操作 | コピー／移動／結合／改名／ごみ箱／Undo／Redo、衝突の全件事前検査、外部変更の拒否 |
| 整理 | 本文検索・保存検索・結果からの選択、正規表現の一括改名、ZIP作成／閲覧／選択展開、比較、ラベル |
| 設定・復旧 | 旧設定／プリセット／表示・タブ・履歴の移行、JSON破損、破損設定での別プロセス起動と原本保持、保存ロック、転送中断と再開前の照合 |
| メディア | 画像・動画・EXRの静止サムネイル、クラウド未取得状態、古い結果の排除、内蔵デコーダー |
| アクセシビリティ | 実UI Automationバックエンドを有効化した表示切替・アイコン寸法変更・セル状態照会。段階読込の行追加で配置が項目ごとに発生しないこと |

個別ケースは`.maya-output/cpp-windows/qpe_cpp_test.exe <ケース名>`でも実行できます。テストは一時ファイルを作成・複製・改名・削除します。出力先は必ず専用領域を使い、同じバイナリの検証と再ビルドを並行させないでください。

## Maya GUIと実再起動

`tests/native_maya_smoke.py`は**専用prefsで起動した検証Maya**内だけで使用します。新規シーンへの切替、保存、Open、Import、Reference、Undo／Redo、sidecar、ドック／フロート、削除・再生成、外部Qt入力、プラグイン解除・再ロードを確認します。作業中のMayaへ送信しないでください。

`tests/native_maya_restart.py`は準備フェーズと別PIDでの確認フェーズを分けます。既に起動しているプロセスのUI再生成を「Maya再起動」とは数えません。autoload、明示的に閉じた状態、浮動位置、ドック状態を分けて記録します。Security確認や別プラグインの起動問題で停止した場合は、その結果を失敗または未実施として残します。

Mayaの年別ビルド成功はGUI動作成功を意味しません。Qt5／Qt6の両方で回帰し、利用するMaya年版と実入力条件を追加で確認してください。

### Maya 2027のドック解除時の描画制限

Windowsの検証環境では、`workspaceControl`をAPIでドックしてからフロートへ戻すと、内容の上端が切れ、下端に描画残りが出る場合があります。Qtのウィジェット画像では正常でも、OS画面ではずれているため、寸法検査や`QWidget.grab()`だけで合格にしないでください。

QPEを一度もロードしていない専用Mayaでも、標準の`workspaceControl`と`columnLayout`・`button`だけで同じ現象を確認しています。QPE固有の不具合とは断定していませんが、QPEの使い勝手にも影響する未解決のホスト側制限です。検証環境ではQPEをアンロードして再ロードし、フローティングUIを作り直すと正常表示へ戻りました。処理中のワーカーがある場合は完了を待ってください。ドラッグによる全ドック操作、全GPU・DPI条件での発生範囲や回避効果は未確認です。他ツールやMaya全体のネイティブウィンドウ属性を変更する対処は行っていません。

## ソースからの再ビルドと再リンク

`tools/prepare_cpp_relink.py`で独立したソース付きフォルダーを作り、そのフォルダーのビルド入口からQt／メディア／QPEを構築します。依存ソースのSHA256、生成exeの依存DLL、PythonやMayaを使わない起動を確認します。

`tests/verify_static_relink.py`は専用SDKのQtバージョン識別文字列を変更し、再リンクしたアプリの実行結果で変更を確認します。最後に元のSDKへ復元します。同じSDKを使用する別ビルドと並行実行しないでください。

## 速度比較

同じ専用ローカルフォルダーで、初回移動・再訪・戻る・タブ切替を分けます。OSキャッシュ、録画、コンパイル負荷の有無と最終件数を記録します。QPEの内部タイマー値とExplorerのOS録画は異なる計測なので、直接の速度倍率として扱いません。ネットワーク、低速ドライブ、シェル拡張やサムネイル条件で変化します。

## 実機で確認する項目

以下は自動イベントや模擬入力だけで合格としません。作業シーンや本番ファイルを避け、検証用コピーを使用してください。

| 操作 | 手順 | 合格条件 |
|---|---|---|
| 物理ホイール | 60件以上ある列の上下端を越えて回す。横ホイール／トラックパッドでも確認 | 別列と背後のMayaビューが動かない。横に戻した位置が読込完了で変わらない |
| 日本語IME | パス・フィルター・改名・名前空間の欄で変換中に矢印、Space、Enter、Escape、Ctrl+C/Vを使う | 変換・編集が優先され、ファイルを開いたり別階層へ移動したりしない |
| 非アクティブ時のクリック | 別アプリを前面にしてからQPEの項目をクリック。Mayaの別ビューでもキーを押す | ホストが配送したクリックのみ一度処理。QPE外のキーでQPEの操作が発火しない |
| 外部ドラッグ | Windows Explorer→QPE、QPE→Explorer、タブ、カラム、第2ペイン、Favoritesへドラッグ。Shift付きも実施 | 表示した行先へコピー／移動。Favoritesはリンク追加。外部アプリでの操作はQPEのUndo対象と混同しない |
| 混在DPI | 通常DPIと4K画面の間でフローティングQPEを移す。ドックでも確認 | 文字、アイコン、行高、境界、ボタンが欠けず、倍率が累積しない |
| ネットワーク中断 | 専用共有フォルダーへのコピー・検索中に接続を切り、中止・再接続を行う | 応答待ちを含め結果を記録。成功扱いにせず、原本と確認可能な履歴を残す |
| OneDrive等 | ローカル保持、オンラインのみ、同期中、プロバイダーの同期エラーを比較 | 自動プレビューでオンラインファイルを取得しない。取得状態とプロバイダーの同期エラーを混同しない |
| Everything | 導入済みのEverythingとes.exeを指定して検索し、実際の場所へ移動 | 結果のパスと条件が一致。未導入時はフォルダースキャンが使える |
| File Locksmith | 対応CLIを設定し、別アプリで開いた検証ファイルを診断 | 使用中プロセスの結果・未対応を区別。プロセスを終了しない |
| OS連携 | Windows Properties、Open with、外部ビューアーを検証ファイルで開く | 正しいファイルを渡す。キャンセルしても選択・原本が変わらない |
| Maya標準オプション | QPEのMaya optionsからOpen／Import／Reference／Save As／Export／Set Projectを開き、キャンセル | 対応するMaya標準画面が開く。通常作業環境へ不用意に設定を保存しない |
| 起動中転送と終了 | 検証コピーの途中でQPEを閉じる。待機ジョブを残してMayaを通常終了し再起動 | 実行中のQPE閉鎖は拒否。保存ジョブは明示再開するまで書き込まない |

P0のAT14・AT19・AT20は自動部分と実入力部分を分け、AT21はホストの実入力で確認します。クラッシュダンプが生成された場合は、終了コードが0でも終了検証の成功とは扱いません。
