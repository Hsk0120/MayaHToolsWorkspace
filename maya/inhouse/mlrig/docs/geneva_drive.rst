ゼネバ機構(GenevaDrive)
=======================

``mlrig.setups.GenevaDrive`` は、連続して回る駆動輪から、溝の付いた従動輪が「止まる・溝1つ分だけ送られる」を
繰り返す間欠回転(ゼネバ機構、外歯車形)の角度を求めます。映写機のフィルム送り・時計・回転テーブル・
ロボットの割り出し機構などを、駆動輪の1つの回転だけでアニメーションできます。
Maya標準ノード(``floor`` ・ ``sin`` ・ ``cos`` ・ ``atan2`` ・ ``divide`` ・ ``animBlendNodeAdditive`` ・
``condition`` ・ ``blendTwoAttr`` ・ ``unitConversion``)だけで組み、独自プラグイン、エクスプレッション、
フレームごとのPythonは使いません。

.. code-block:: python

   from mlrig.setups import GenevaDrive

   # 溝が4本の従動輪。駆動輪を1回転させるごとに従動輪が90度送られる
   graph = GenevaDrive.create("driver_wheel", "geneva_wheel", slots=4, name="indexer", axis="z")
   owner = graph.container
   # 従動輪の rotateZ へ出力を接続済み。駆動輪の rotateZ を回すだけで動く

``connect=True`` (既定)なら従動輪の ``rotate<axis>`` へ出力を接続します。 ``False`` なら接続せず、
containerの ``rotate`` を自分で使います。

参考にした考え方
----------------

* ピンが溝へ接線方向に入るよう、ピンの半径 r と軸間距離 c の比を ``r / c = sin(π/n)`` にする外歯車形の標準の寸法、
  溝1つ分の送り角 ``360° / n`` 、ピンが溝に入っている駆動輪の角度 ``180° - 360°/n`` という一般的な設計の関係
  (https://www.purdue.edu/freeform/me274/course-material/animations/the-geneva-mechanism 、
  https://www.firgelliauto.com/blogs/mechanisms/geneva-drive)。
* 従動輪の角度は、軸間の線・ピン・従動輪の中心がなす三角形から ``tan β = λ sin α / (1 - λ cos α)`` で求まる、という幾何
  (この部品で式を導き、試験側でピンの位置から独立に確かめました)。

いずれもコードは流用していません。

引数
----

* ``driver``: 駆動輪(ピンの付いた輪)のtransform。ローカルの ``rotate<axis>`` を回します。
  生成時の姿勢を、ピンが従動輪と反対側にある休止の中央( ``θ = 0`` )とします。
* ``wheel``: 従動輪(溝の付いた輪)のtransform。
* ``slots``: 従動輪の溝の数(3以上の整数)。生成時に固定します。
* ``axis``: 両方の輪のローカルの回転軸(x/y/z)。
* ``connect``: Trueなら従動輪の ``rotate<axis>`` へ出力を接続します。既に入力がある場合は ``ValueError`` です。

計算式
------

``n`` は溝の数、 ``λ = r / c = sin(π/n)`` 、 ``α0 = 90° - 180°/n`` (ピンが溝に入っている範囲の半分)です。

1. ``θ = 駆動輪の rotate<axis> - 生成時の値`` 、 ``k = floor(θ / 360°)`` (駆動輪の回転数)。
2. ``α = θ - 180° - 360°·k`` (軸間の線から測ったピンの角度、-180°〜180°)。
3. ``α' = clamp(α, -α0, α0)`` 、 ``β = atan2(λ sin α', 1 - λ cos α')`` (溝の角度)。
4. ``indexAngle = φ = 360°·k / n + 180° / n + β`` 、 ``rotate = 生成時の従動輪の rotate<axis> + phase - φ`` 。
5. ``speedRatio = dφ/dθ = λ(cos α' - λ) / (1 + λ² - 2λ cos α')`` 。

β は α = ±α0 で最大(±180°/n)になるので、α を止めてから β を求めると、休止中は従動輪が止まり、
溝へ出入りする瞬間も角度と速度比が連続します(ピンが接線方向に入るので速度比は0から立ち上がります)。
θ = 0 では φ = 0 なので、接続しても従動輪は跳ねません。駆動輪を1回転させると従動輪は ``360° / n`` 送られ、
外歯車形なので駆動輪と逆向きに回ります。駆動輪を逆に回すと従動輪も戻ります(履歴を持たない閉じた式)。
速度比は溝の中央( α = 0 )で最大 ``λ / (1 - λ)`` (4本溝で約2.41)です。

数値の加算は ``animBlendNodeAdditive`` を連ねて倍精度で行います(``plusMinusAverage`` ・ ``multiplyDivide`` は単精度のため)。
``floor`` ・ ``sin`` ・ ``atan2`` 等の入出力はMaya 2025では長さの型なので、係数を明示した ``unitConversion`` を挟み、
UI単位(mm・ラジアン等)に関係なく同じ結果にします。

containerのアトリビュート
--------------------------

* ``phase`` : 従動輪に足す角度(keyable)。溝の向きの見た目を合わせるのに使います。
* ``rotate`` : 従動輪の回転(出力)。
* ``indexAngle`` : 従動輪が送られた角度 φ (確認用、駆動輪と同じ向きを正)。
* ``crankAngle`` : 軸間の線から測ったピンの角度 α 。
* ``engaged`` : ピンが溝に入っている間1、休止中は0。
* ``speedRatio`` : 駆動輪に対する従動輪の角速度の比(休止中は0)。音・揺れ・ブレのドライバーに使えます。
* ``step`` : 駆動輪の回転数 k 。

制限
----

* 駆動輪はローカルの1軸の回転チャンネル( ``rotate<axis>`` )を読みます。複数軸の回転やワールドでの回転は扱いません。
* 寸法は標準の比( ``r / c = sin(π/n)`` 、ピン1本)に固定します。ピンが2本以上の形、内歯車形、球面ゼネバは扱いません。
* 輪の位置と形状(溝・ロック用の三日月形のカム)は作りません。軸間距離 c 、ピンの半径 ``c·sin(π/n)`` の位置に置くのは利用側です。
* 歯のガタ・慣性による行き過ぎはありません(角度は駆動輪の角度だけで決まります)。

テスト
------

``mlrig/__tests__/test_setup_geneva_drive.py`` (``setups`` スイート)で、原点の従動輪と軸間距離6cmの駆動輪(子のピン)を作り、
作成直後に従動輪が跳ねないこと、溝に入っている間は従動輪のローカルで見たピンが常に溝の線の上にあること(試験側で独立に計算)、
休止中は従動輪が止まり1回転ごとに90度送られること(正負の回転)、溝へ出入りする角度と段の切り替わりで連続すること、
Python版( :meth:`GenevaDrive.motion` )との一致と速度比の数値微分との一致、 ``phase`` ・溝6本・ ``axis = x`` ・UI単位mm/ラジアン、
containerの所有とUndo/Redo、引数の検査を確認します。Maya 2027で確認しています。

検証動画
--------

``tools/demo_geneva_drive.py`` は、新規シーンに4本溝の従動輪(緑、白い目印の溝)と駆動輪(赤、黄色のピン)を正面から見る構図で作り、
駆動輪を1回転→2回転目→逆回転で溝の中へ戻す→元へ戻す動きで、式と毎フレームの θ ・ k ・ α ・溝に入っているか・
従動輪の回転・ β ・速度比をHUDに表示して録画します。各フレームでDGの出力がPython版と一致し、溝に入っている間は
ピンが溝の線の上にあることを判定します。

新規シーンを作るため、作業中のMayaへは送りません。次のコマンドは隔離した使い捨てのMaya 2027 GUIを起動して録画し、
終了後に閉じます。結果は ``.maya-output/verification/<実行ID>/`` に保存し、最新のフォルダーを ``latest-geneva-drive.json`` に記録します。

.. code-block:: powershell

   $env:MAYA_VERIFICATION_FFMPEG = "C:/path/to/ffmpeg.exe"
   python tools\demo_geneva_drive.py --launch
