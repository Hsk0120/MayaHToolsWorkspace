凹凸のある地面への接地(UnevenGround)
=====================================

``mlrig.setups.UnevenGround`` は、**平らな床の上で付けた左右の足と腰の動きを、足の下の地面の高さと傾きに
合わせて後から補正します**。歩き・立ち・構えのアニメーションは平らな床で作っておき、坂や段差のある場所では
アニメーション自体(足と腰のコントロール)を書き換えずに、表示する結果だけを地面に合わせる、という一般的な
考え方です。足は真下の地面の高さだけ持ち上がって足裏が地面の傾きに沿い、腰は低い方の足に合わせて下がるので、
脚が届かずに伸び切ることを避けられます。

* 平らな床で作った歩きや待機のモーションを、坂・階段・起伏のある地面の上で使いたいとき。
* 足が地面にめり込む・浮くのを、アニメーションのキーを直さずに後処理で直したいとき。
* 足ごとに違う高さ・傾きの地面(段の上と下、坂の途中)に立たせたいとき。

4本の足の面から胴体を傾ける GroundTilt、足首・つま先の回転で転がす FootRoll、平面より下へ沈まないよう
押し出す PlaneCollision とは別のもので、こちらは2本足の足と腰の上下と足裏の傾きを、足の下の地面から決めます。
Maya標準ノード(``vectorProduct`` ・ ``plusMinusAverage`` ・ ``aimMatrix`` ・ ``fourByFourMatrix`` ・
``blendMatrix`` ・ ``multMatrix`` ・ ``condition`` など)だけで組みます。独自プラグイン、エクスプレッション、
フレームごとのPythonは使いません。生成したノードはcontainerが所有します。

.. code-block:: python

   from mlrig.setups import UnevenGround

   # 左右の足のIKコントロールと腰のコントロール(平らな床の上で動かす)と、足ごとの地面。
   ground = UnevenGround.create("hips_ctrl", "foot_L_ctrl", "foot_R_ctrl", "ground_L", "ground_R",
                                name="unevenGround")
   # 出力は受け側へつなぐ(入力のコントロールへはつながない)。
   cmds.connectAttr("unevenGround.leftFootMatrix", "leg_L_ik_target.offsetParentMatrix")
   cmds.connectAttr("unevenGround.rightFootMatrix", "leg_R_ik_target.offsetParentMatrix")
   cmds.connectAttr("unevenGround.hipsMatrix", "pelvis_driven.offsetParentMatrix")

   # Python版: 同じ式のワールド行列と持ち上げの量
   UnevenGround.placement(hips, leftFoot, rightFoot, leftGround, rightGround)["hipsOffset"]

地面は、足ごとの平面を表す transform(原点が地面の上の点、 ``groundAxis`` (既定は Y)が法線)で与えます。
左右に同じ transform を渡せば1枚の坂になります。メッシュの地面に合わせる場合は、その transform を地面へ
貼り付けて(follicle や ``closestPointOnMesh`` など)足の位置に付いて動くようにします。

式
--

ワールド空間で、Y が上です。左右の足ごとに、 ``p`` を足の位置、 ``g`` を地面の transform の位置、 ``n`` を地面の
``groundAxis`` のワールドの単位ベクトル(法線)とします。

* 足の真下(真上)の地面の高さ ``y_g = p.y + ((g - p)·n) / max(n.y, 0.05)`` (足を通る鉛直な線と地面の平面の交点)。
* 足の持ち上げ ``h = height · (y_g - floorHeight)`` 。足が床から浮いている分(振り出し・ジャンプ)はそのまま残り、
  床の代わりに地面の高さが基準になります。
* 地面の傾き: ``A0`` = Y を世界の上、 ``forwardAxis`` を足の前へ揃えた向き、 ``A`` = Y を ``n`` 、
  ``forwardAxis`` を足の前へ揃えた向き(どちらも ``aimMatrix`` で、前は上の軸に直交させる)。
  ``D = A0^-1 · A`` は世界の上を ``n`` へ移し、足の前の水平の向きを「足の前を ``n`` の方向に地面の面へ投影した
  向き」へ移す回転で、足の進む向きを大きく変えずに足裏を地面の傾きへ合わせます。 ``A0`` は回転だけなので、
  逆行列は転置( ``fourByFourMatrix`` )で求めます。
* ``Dt = slerp(単位行列, D, align)`` (``blendMatrix``)。
* 足の出力 ``F' = F · T(-p) · Dt · T(p + h·Y)`` (``F`` は足の現在のワールド行列、行ベクトルの書き方)。
  足の位置を中心に回し、真上へ ``h`` だけ動かします。

腰は、低い方の足の持ち上げに合わせて上下させます。

* ``hipsOffset = hips · min(h_left, h_right)`` 。片足が段の上なら、腰は低い方(段の下)の足に合わせて下がり、
  両足が段の上なら上がります。
* 腰の出力 ``H' = H · T(0, hipsOffset, 0)`` (``H`` は腰の現在のワールド行列。回転は変えません)。

地面が床の高さ(``floorHeight``)で水平なら ``h = 0`` 、 ``D`` は単位行列で、出力は入力と同じです(作成時に跳ねない)。
時刻・前の結果を使わないので、どのフレームでも同じ配置から同じ値になります。

containerのアトリビュート
-------------------------

.. list-table::
   :header-rows: 1

   * - アトリビュート
     - 内容
   * - ``floorHeight``
     - アニメーションを付けた平らな床のワールドの高さ(cm)。既定は0。
   * - ``height``
     - 地面の高さを足へ加える割合。0で補正なし、1で地面の上。
   * - ``align``
     - 足裏を地面の傾きへ合わせる割合(0〜1)。
   * - ``hips``
     - 低い方の足の持ち上げを腰へ加える割合。
   * - ``hipsMatrix`` ・ ``leftFootMatrix`` ・ ``rightFootMatrix``
     - 出力。補正後の腰・左足・右足のワールド行列。
   * - ``leftOffset`` ・ ``rightOffset`` ・ ``hipsOffset``
     - 出力。左右の足と腰の上下の量(cm、確認用)。

制限
----

* 地面は足ごとの平面です。足の大きさより細かい凹凸(つま先とかかとで高さが違う段の角など)は表しません。
  つま先・かかとを別々に合わせたい場合は、つま先・かかとの位置ごとに使い、足の向きは利用側で決めます。
* 法線の上向きの成分 ``n.y`` が0.05より小さい(垂直に近い)地面は、割り算が発散しないよう0.05として扱います。
  作成時の地面の法線が下向き・水平に近い場合は ``ValueError`` になります。
* 出力は入力のノードへはつなぎません(入力を書き換えると循環します)。受け側の ``offsetParentMatrix`` へ入れる
  場合は、受け側の親が動くなら親の ``worldInverseMatrix`` を掛けてからつなぎます。
* 膝の向き・脚の長さの制限は扱いません。腰を下げても届かない場合は、IKの伸び(limbStretchLayer など)で補います。

試験
----

``mlrig/__tests__/test_setup_uneven_ground.py`` (``setups`` スイート)で、回転した親の下の2枚の地面と、
回転した腰・左右の足について、床の高さで水平な地面なら作成直後の出力が入力と同じであること、足・地面・腰・
``floorHeight`` の乱数25通りで、足の位置から床からの高さを引いた点が地面の平面の上にあること・足の回転の差が
世界の上を法線へ移し足の前を地面の面へ投影した向きへ移すこと・腰が低い方の足の持ち上げだけ上下し回転が
変わらないこと(試験側で独立に書いた条件)と Python版との一致、左右に同じ1枚の坂を使う場合の値(20度の坂で
``10·tan20°``)、 ``height`` ・ ``align`` ・ ``hips`` の割合( ``align=0`` で回転が変わらず、0.5で角度が半分)、地面の法線・
足の前の軸3通り、DG・serial・parallel の各評価で古い値にならないこと、container所有と入力へ接続しないこと・
Undo/Redo、引数13種で何も残さないことを確認します。

参考にした考え方
----------------

* 平らな床で作ったアニメーションを、坂のある場所では計算用の姿勢を平らなまま保ち、表示用の骨にだけ地面の
  凹凸を反映して足を接地させる、という一般的な後処理の考え方。
* 足の下の地面の高さだけ足を上げ、腰を低い方の足に合わせて下げる、2本足のキャラクターの足の接地
  (foot placement)の一般的な手順。コードは流用していません。
