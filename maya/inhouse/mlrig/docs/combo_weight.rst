組み合わせのウェイト(ComboWeight)
==================================

``mlrig.setups.ComboWeight`` は、いくつかのウェイト(ドライバー)から、補正シェイプや補助骨を動かすための
**組み合わせのウェイト** と **途中のウェイト** を求めます。

* 組み合わせのウェイトは、含むドライバーがすべて動いたときだけ大きくなる値です。たとえば左右の口角を
  それぞれ上げるシェイプを同時に使うと、2つの移動が足されて口の真ん中まで上がりすぎます。左右の両方が
  動いたときだけ効く補正シェイプ(足しすぎた分を戻すシェイプ)を、組み合わせのウェイトで動かすと直せます。
  左右・上下など、別々に作ったシェイプを同時に使うときに崩れる所を直す一般的な方法です。
* 途中のウェイトは、1つのドライバーが途中の位置(たとえば0.5)のときに1、0と1のときに0になる山形の値です。
  ブレンドシェイプのインビトウィーンと同じ時点で、別の補正シェイプや補助骨を動かすときに使います。

Maya標準ノード(``clamp`` ・ ``animBlendNodeAdditive`` ・ ``condition``)だけで組み、独自プラグイン、
エクスプレッション、フレームごとのPythonは使いません。生成したノードはcontainerが所有します。

.. code-block:: python

   from mlrig.setups import ComboWeight

   combo = ComboWeight.create(
       {"left": "mouthL_ctrl.translateY", "right": "mouthR_ctrl.translateY"},
       {"both": ["left", "right"]},
       {"leftHalf": ("left", 0.5)},
       name="mouthCombo")
   cmds.connectAttr("mouthCombo.left", "mouthBlend.smileL")
   cmds.connectAttr("mouthCombo.right", "mouthBlend.smileR")
   cmds.connectAttr("mouthCombo.both", "mouthBlend.smileFix")

``drivers`` に名前だけの並びを渡すか、入力を ``None`` にした名前は、containerの keyable なアトリビュート
(既定0)を直接動かします。入力のアトリビュートを渡した名前は、その値がcontainerのアトリビュートへ接続されます。

式
--

ドライバーの値は ``0`` 〜 ``1`` に切り詰めてから使います(``x' = clamp(x, 0, 1)``)。

* 組み合わせ(``method="multiply"``、既定): ``w = a' · b' · …`` (積)。片方が0なら0、両方が1なら1。
  両方が0.5なら0.25と、ゆっくり立ち上がります。
* 組み合わせ(``method="lowest"``): ``w = min(a', b', …)`` (最小)。両方が0.5なら0.5と、
  一番動いていないドライバーに合わせて直線的に立ち上がります。
* 途中のウェイト(位置 ``p``、 ``0 < p < 1``): ``w = min(x' / p, (1 - x') / (1 - p))`` 。
  ``x' = p`` で1、 ``x' = 0`` と ``1`` で0、その間は一次式です。

積と山形の一次式は倍精度の ``animBlendNodeAdditive`` (``inputA · weightA + inputB · weightB``) で、
最小は ``condition`` (``firstTerm < secondTerm``) で求めます。3つ以上のドライバーの組み合わせは、
2つずつ順に掛ける(最小を取る)ノードの列になります。

containerのアトリビュート
-------------------------

.. list-table::
   :header-rows: 1

   * - 名前
     - 内容
   * - ドライバー名(``drivers`` のキー)
     - 入力のウェイト(keyable、既定0)。入力のアトリビュートを渡した場合はそこから接続される。
   * - 組み合わせの名前(``combos`` のキー)
     - 組み合わせのウェイト(出力)。
   * - 途中のウェイトの名前(``inbetweens`` のキー)
     - 途中のウェイト(出力)。
   * - ``comboMethod``
     - 組み合わせの求め方(``multiply`` / ``lowest``、作成時の値の記録。変えても式は変わらない)。
   * - ``driverNames`` ・ ``outputNames``
     - ドライバー名・出力の名前(空白区切り)。 ``getDrivers()`` ・ ``getOutputs()`` が読みます。

Python版の ``ComboWeight.evaluate(values, combos, inbetweens, method)`` は、出力の名前と値の辞書を返します。

制限
----

* ``clamp`` と ``condition`` は単精度なので、値の誤差は 1e-7 程度です(試験の許容は 1e-6)。
* containerのドライバーのアトリビュートは入力の値そのもので(1を超えた分もそのまま)、切り詰めるのは組み合わせ・途中のウェイトの計算の中だけです。
  左右のシェイプをドライバーのアトリビュートから動かすと、1を超えた入力ではシェイプも1を超えて効きます(補正は1で止まる)。
* ドライバーは 0〜1 の範囲だけを使います。負の向き(口角を下げる等)は別のドライバーにします
  (コントロールの値を正負に分けるには :doc:`ui_slider` などを使う)。
* 組み合わせの補正シェイプ自体(どれだけ戻すか)は利用側で作ります。補正シェイプは、左右のシェイプを
  両方1にしたときの形との差として作るのが一般的です。
* 組み合わせの求め方は作成時に決まり、あとから ``comboMethod`` を変えても切り替わりません(作り直す)。

試験
----

``mlrig/__tests__/test_setup_combo_weight.py`` (``setups`` スイート)で、3つのドライバーの格子と範囲外を含む乱数に対して
積・最小・山形が試験側の独立計算・Python版と一致すること、山形の頂点と端、入力のアトリビュートからの接続、
実際のブレンドシェイプ(左右のシェイプと補正シェイプ)で左右を同時に上げても真ん中の頂点が片側だけのときと同じ高さになること、
container所有とUndo/Redo、引数を確認します。

参考にした考え方
----------------

* 左右や上下に分けて作ったブレンドシェイプを同時に使うときに、両方のウェイトの積で動かす組み合わせの
  補正シェイプを足す一般的な方法(Mayaのブレンドシェイプの組み合わせターゲットの、積・最小のウェイトの求め方)。
* ブレンドシェイプのインビトウィーン(ウェイトが途中の値のときに経由する形)と同じ時点で別の補正を動かす考え方。
