# hlibのGUI検証

数値・属性値・Undoの検証は[バージョン別テスト](hlib-testing.md)、実パネルへの適用と表示はこのGUIスイートで確認します。自動アサーションの成功と画像の目視確認は別の結果です。

## 実行

### 全バージョンを専用GUIで実行

```powershell
& 'C:/Program Files/Autodesk/Maya2027/bin/mayapy.exe' tools/run_hlib_gui_versions.py --allow-missing
```

Maya 2022～2027を順番に起動します。各GUIは専用の設定・一時フォルダーを使用し、commandPortは使用しません。テスト終了後は、このランナーが起動したMayaだけを終了します。`--versions 2024 2027`で対象を限定できます。GUI版の起動に必要なライセンス認証は通常どおり必要です。

結果は`.maya-output/gui-version-tests/<日時>/summary.json`、各バージョンの`result.json`・ログ・PNGに保存します。起動失敗やライセンスエラーで結果を取得できない場合は成功扱いにしません。`--timeout`は起動・テストの各段階の制限秒数（既定240秒）、`--shutdown-timeout`はテスト後の終了待ち秒数（既定15秒）です。外側のPythonが監視するため、Mayaがモーダルダイアログで停止しても期限は進みます。超過時はランナーが起動したPIDと子プロセスだけを終了し、`monitor.json`へ段階・停止結果を保存します。`--allow-missing`は未インストールだけを終了コードの失敗判定から除外し、テスト失敗・起動失敗は除外しません。画像の目視確認と手動操作は下記の確認対象に従って別途記録します。

専用の`userPrefs.mel`では`SafeModeExecUserSetupScript=0`とし、追加のuserSetupを実行しません。チェックサム確認を無効化してスクリプトを信頼する設定ではありません。普段使う設定は変更しません。終了前には使い捨てシーンの変更済みフラグを解除し、Pythonコールバックを抜けてからMELの`quit -abort`で終了します。途中で手動クリックした場合、その回を無人実行成功とは記録しないでください。

テスト後のMaya終了が滞留した場合もランナーは`timeout`を返します。`suite_status`と`timeout_phase`で、テスト本体の結果と終了時のタイムアウトを区別できます。`result.json`の成功だけで、プロセスが正常終了したと判断しないでください。

### 起動済みGUIに送信

ワークスペースのバッチからMayaを起動し、再生を停止し、Undoを有効にしてください。commandPort `127.0.0.1:7002`へ送信します。複数バージョンを同時に起動せず、検証対象だけを接続してください。

リポジトリ直下のPowerShellで実行します（制御用PythonはMayaの実行バージョンを決めません）。

```powershell
& 'C:/Program Files/Autodesk/Maya2027/bin/mayapy.exe' tools/test_hlib_gui.py
```

`run_hlib_gui_tests.py`はMaya内で専用パネルを作り、アイドル処理後に実行します。送信完了だけではテスト完了ではないため、上記ランナーが最終JSONまで待機します。終了コード0は自動アサーション成功、1は失敗、2は送信・待機などの異常です。タイムアウト時もMaya内の処理はキャンセルされません。結果を確認せず再送しないでください。

結果は`.maya-output/gui-tests/<日時>/`の`result.json`、`tests.log`、PNGへ保存します。画像の`review: pending`は未確認です。別途`review.json`へ確認者・各画像の判定と根拠を記録します。描画バッファには通知などのUIオーバーレイが含まれない場合があり、画像の保存成功だけを表示成功としません。

専用名前空間・カメラ・Outliner・ビューポート・Channel Boxを作り、最後に削除します。選択・時刻・フォーカスを復元し、既存テストの一時設定も復元します。シーンの新規作成・保存・既存ノード編集は行いません。ただし検証操作はUndo履歴とシーンの変更済み状態に影響します。専用の検証セッションを推奨します。クリーンアップ失敗もテスト失敗として報告します。

## 実装からの検証対象一覧

| 対象 | 自動確認 | 表示・操作の確認範囲／残る手動確認 |
| --- | --- | --- |
| NodeのOutliner色／Shapeのoverride色 | 色設定・解除・Undo・Redo | RGBとインデックス色、各段階の文字色とカーブ色をPNG確認 |
| Viewport | 表示フラグ、カメラ照会、例外・ネスト時の設定復元 | カーブ非表示→復元、対象カメラの描画をPNG確認。カメラの切替操作は追加手動確認 |
| Viewportの画面更新停止 | メインペインのmanage状態、例外・ネスト・元から停止時の復元 | 停止中の実際の更新抑止と復帰後の操作性は手動確認 |
| Outliner | 設定復元、展開・折畳コマンド | 親子階層を作り、全展開／折畳後のツリーを手動確認。静的リストの画像だけでは階層表示を保証しない |
| ChannelBox | 実コントロールの属性選択、Plug取得、選択解除 | main/shape/history/output各欄のマウス選択と見た目。Qtキャプチャが空の場合は未確認として扱う |
| TimeSlider | 時刻・再生範囲・アニメーション範囲、復元、再生／停止状態 | Shiftドラッグの選択範囲と実フレーム進行は手動確認 |
| Selection | コンポーネント選択の保存・復元 | CVのハイライトをPNG確認。頂点・辺・面・UVの各選択モードも手動確認 |
| Plug／Nodeの属性表示設定 | 値・keyable/channelBox/lock等は既存の単体テスト | 非表示・ロック・属性順序変更のChannel Box表示は手動確認 |
| MayaHandler | 実GUIで警告発行、例外なし | Script Editorの警告とinViewMessageの表示・消えるタイミングは手動確認 |
| ファクトリー関数・パネル解決 | 有効／無効UI名、ラッパー取得 | 複数パネルでフォーカスを変えた既定パネル選択は手動確認 |

幾何・行列・ウェイト・ファイル・名前空間など、データとして結果を検証できる処理すべてにGUIテストを追加する必要はありません。`utils/progress.py`はテキスト出力でありGUIプログレスバーではありません。外部プラグイン独自UIやSphinxブラウザー検証は別の検証範囲です。

## 手動チェックの手順

1. 検証用シーンで親子TransformとShapeを用意し、Outlinerの表示設定・全展開・折畳を切り替える。実ツリーの子項目が増減することを確認する。
2. 履歴付きのShapeを選択し、Channel Boxの各欄をマウス選択する。`hlib.channelBox().selected_plugs()`と画面の選択属性が一致すること、解除・ロック・表示設定・属性順序が画面へ反映されることを確認する。
3. タイムスライダーをShiftドラッグして選択し、`hlib.timeSlider().selected_range()`と比較する。再生中に時刻が進み、停止できることを確認する。
4. ビューポートのカメラ切替、画面更新停止コンテキストの終了／例外後の再描画を確認する。別パネルへフォーカスを移し、既定のラッパーが目的のパネルを選ぶか確認する。
5. ロガーの警告を発行し、Script Editorとビューポート内の通知、フェードを確認する。頂点・辺・面・UV選択について保存→解除→復元のハイライトを確認する。

Maya 2022～2027では各GUIを個別に起動して繰り返します。standaloneでの全バージョン成功をGUI検証の代わりにはしません。実施バージョン・画像判定・未実施項目は各回の結果へ記録してください。
